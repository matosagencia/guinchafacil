1. Banco de dados (obrigatório)
install/guinchafacil.sql

Adicionar a nova configuração.

Exemplo:

system_mode = production

ou

payment_required = 1
migrations

Dependendo de como estão organizadas:

install/migration_*.sql

ou criar uma nova:

migration_vX_system_mode.sql

que fará:

ALTER TABLE configuracoes
ADD COLUMN payment_required TINYINT(1) NOT NULL DEFAULT 1;

ou

ADD COLUMN system_mode ENUM(
'production',
'sandbox',
'freeflow'
)
2. Backoffice (Admin)
src/Controllers/AdminController.php

Esse será o principal.

Será responsável por:

carregar configuração
salvar configuração
validar alteração

Provavelmente também haverá a view correspondente.

Algo como:

views/admin/configuracoes.php

ou

views/admin/settings.php

Precisamos localizar qual delas existe.

Ali será inserido:

Modo de operação

( ) Produção

( ) Sandbox

( ) Fluxo Livre
3. Camada de pagamento

Aqui é onde quero mexer o mínimo possível.

Precisamos localizar exatamente onde hoje ocorre:

Pedido

↓

MercadoPago

↓

approved

↓

libera atendimento

Provavelmente existe algo como:

PagamentoController.php

ou

MercadoPagoService.php

ou

PaymentService.php

ou

MercadoPagoWebhook.php

Ali apenas adicionaremos:

if ($config->system_mode == 'freeflow') {

    // pagamento virtual

}

Nada mais.

4. Fluxo do pedido

Esse é o ponto mais importante.

Precisamos descobrir onde existe algo parecido com:

if ($pedido->payment_status != 'approved')

ou

if (!$pedido->isPaid())

Esse trecho deverá passar a utilizar algo como:

PedidoService::podeIniciarAtendimento()

Assim toda regra fica centralizada.

5. API do Cliente

Muito provavelmente teremos um endpoint semelhante a:

POST /pedido

ou

POST /checkout

Ele deverá deixar de responder:

Vá para pagamento

e responder:

Pedido criado

Aguardando guincho

quando estiver em Fluxo Livre.

6. App Cliente

Provavelmente haverá uma Activity/Fragment equivalente a:

CheckoutActivity

PagamentoActivity

PedidoActivity

Hoje o fluxo é:

Pedido

↓

Pagamento

↓

Busca Guincho

Passará a ser:

Pedido

↓

Busca Guincho

somente quando:

system_mode == freeflow

Sem remover nenhuma tela.

Apenas ocultando.

7. App Guincho

Em princípio quase nada muda.

Ele apenas começará a receber pedidos normalmente.

Não deve sofrer alterações estruturais.

8. Chat

Conclusão
9. Logs

Gostaria de acrescentar apenas um log.

Exemplo:

[Payment] Flow Mode = FREEFLOW

Pedido liberado sem gateway.

Assim nunca haverá dúvida do motivo pelo qual o pedido foi liberado.

Minha estimativa

Eu acredito que essa funcionalidade afetará aproximadamente 8 a 12 arquivos, distribuídos assim:

Componente	Arquivos
Banco de dados	1–2
Admin (controller + view)	2
Configuração global	1
Serviço/Controller de pagamento	1–2
Serviço/Controller de pedidos	1–2
API Cliente	1
App Android Cliente	2–3

Como agora você me enviou o ZIP completo do GuinchaFácil, eu prefiro fazer um levantamento cirúrgico dos arquivos reais do projeto, em vez de trabalhar com estimativas. Vou mapear exatamente onde estão:

o controller do Mercado Pago;
o serviço de pagamento;
o controller de criação do pedido;
o ponto em que o atendimento é liberado;
